UNICODE / TEXT RENDERING CORRUPTION — DIAGNOSIS REPORT
=======================================================

SYMPTOM
-------
Every st.expander label in the Nutrition & Meal Recommendations section
displays as "_arr▯vDaig▯t" (garbled) instead of "📅 Day 1", "📅 Day 2", etc.

ROOT CAUSE
----------
CSS over-ride breaks the Material Symbols icon font on the expander header.

Streamlit 1.59.x renders the expand/collapse toggle inside st.expander() as
a <span> (or inline element) that uses the "Material Symbols" font.
That font uses Unicode LIGATURES — it maps the text string "arrow_drop_down"
or "expand_more" to a single rendered icon glyph.

Two CSS rules in assets/style.css override the font-family on the entire
<summary> element AND every child span:

  Rule 1 (line 1250, Section 22):
    .stExpander summary {
      font-family: var(--font) !important;   ← forces Inter onto summary
    }

  Rule 2 (lines ~200-203, Section 4):
    p, li, div, span, label {
      font-family: var(--font) !important;   ← forces Inter onto ALL spans
    }

Because the icon span inherits Inter (not Material Symbols), the ligature
string (e.g. "arrow_drop_down") renders as plain Inter text. Combined with
the 4-byte emoji 📅 (U+1F4C5) that Streamlit may process into an icon
shortcode, the visual result is the garbled "_arr▯vDaig▯t" seen on screen.

PROPOSED MINIMAL FIX
---------------------
1. In assets/style.css:
   a. Remove font-family from .stExpander summary (keep all other properties)
   b. Add an explicit EXCEPTION to the global span/div rule to exclude
      Streamlit's Material icon spans from the font override.

2. In recommendation.py (or wherever food names are prepared for display):
   Add a clean_display_text() helper that strips mojibake artifacts from
   food names without touching emojis or legitimate Unicode.

3. Change the expander label from f"📅 {day_name}" to f"📆 {day_name}" OR
   use plain text "Day 1", "Day 2" without an emoji prefix, to completely
   avoid the emoji-to-icon-ligature conversion in Streamlit.
